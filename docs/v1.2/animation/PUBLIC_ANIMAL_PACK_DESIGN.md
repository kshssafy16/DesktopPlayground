# 공개용 기본 동물팩: 7종 애니메이션 설계 초안

2026-10-15 사용자 요청 기준. 기존 5종 후보를 **콜덕·아기 하프물범·아기 펭귄·닥스훈트·웰시코기·말티즈·포메라니안** 7종으로 확장한다. 돌고래·범고래는 후순위 후보다. 이번 문서는 제작 설계이며 이미지 제작·앱 등록·출시 일정 확정을 의미하지 않는다. 기존 9종과 별개로 공개 배포할 오리지널 동물 디자인을 준비한다. 유명 캐릭터의 얼굴·의상·소품을 차용하지 않는다.

프로필 초안은 `animation/drafts/public-animals.v1.draft.json`에 있다. `animals[id].profile`만 기존 `profile-authoring.schema.json` 형식이며, 바깥의 상태·포즈·방향 메타데이터는 제작용이다. 파일 전체는 런타임 카탈로그가 아니며 브라우저 프로필 생성기의 입력에 포함하지 않는다. 이미지가 없는 동물의 행·열·anchor는 **제작 목표 좌표**이고 측정 완료값이 아니다. 콜덕·아기 하프물범·아기 펭귄은 별도 조립이 끝났으므로 실제 프레임 매핑은 각 `deliverables/*_ready/animation/*.profile.json`과 패키지의 `docs/FRAME_MAPPING.md`를 우선한다.

모든 시트는 8열, 셀 192×208, 투명 WebP를 목표로 한다. 셀 안쪽 좌우 12px·상단 12px 이상 여백, 기준 가로축 x=96, 접지선 y=192를 제작 가이드로 사용한다. 초안은 `origin:feet`, `center:0.5`, `foot:192/208`, `scale:1`, `sleeping:false`로 통일한다. `feet`는 물범의 배와 같은 **지면 접촉 기준점**도 뜻하며 없는 발을 그리는 지시가 아니다. 공중 포즈에도 동일한 가상 기준점을 두고, 물리 이동과 별도로 셀 전체를 위아래로 옮기지 않는다. 원화 승인 뒤 실제 측정으로 확정한다.

대칭 디자인의 첫 패키지는 `walkLeft.mirrorOf:walkRight`를 사용한다. 비대칭 무늬가 확정되면 예약된 2행에 왼쪽 그림을 제작하고 반전을 제거한다. 앞모습 idle·공중·수면·held는 걷기 클립의 반전을 물려받지 않는다. 방향별 공중 그림까지 요구할 경우 현재 상태 이름만으로 자동 선택되지 않으므로 앱 계약을 추가 검토한다.

닥스훈트는 기본 몸길이를 셀 안쪽 160px 이하로 설계하고 최대 약 5%의 몸통 늘어남을 원화로 표현한다. 머리·발 크기를 유지하며 uniform `scale`로 몸 전체를 키우지 않는다. 복슬복슬한 두 종은 털 끝까지 여백 안에 넣고 흰 배경·어두운 배경 모두에서 외곽과 알파 경계를 확인한다. 종 사이의 비율은 다르게 하되 같은 종의 전환에서 머리 크기나 몸통 두께가 갑자기 달라지면 안 된다.

## 상태별 연기

아래 움직임은 그림과 재생 연기 지시다. 실제 위치·속도·점프 높이·충돌 판정은 기존 앱 물리가 담당한다. 콜덕·물범·펭귄도 기존 지상 이동과 점프를 사용하며 새 이동 물리를 전제하지 않는다. hit는 짧은 놀람이며 울음이나 부상 묘사를 수면에 섞지 않는다.

## 프레임 예산과 프로필 초안

프레임 수는 **상태당 서로 다른 그림 수**다. 반복 배열 길이·미러 방향을 별도 원화 수로 더하지 않는다. 왼쪽을 독립 제작하면 보행 원화 수가 추가된다. 아래 범위에서 초안 JSON은 대표 수량 하나를 선택했다. 실제 제작 후 불필요한 그림은 줄일 수 있다.

| 아기 펭귄 | 4–6 | 6–8 | 2–3 / 1–2 / 2–3 | 2–4 | 1 | 2–3 | 4–6 |
| 닥스훈트 | 4–6 | 6–8 | 2–3 / 1–2 / 2–3 | 2–4 | 1 | 2–3 | 4–6 |
| 웰시코기 | 4–6 | 6–8 | 2–3 / 1–2 / 2–3 | 2–4 | 1 | 2–3 | 4–6 |
| 말티즈 | 4–6 | 6–8 | 2–3 / 1–2 / 2–3 | 2–4 | 1 | 2–3 | 4–6 |
| 포메라니안 | 4–6 | 6–8 | 2–3 / 1–2 / 2–3 | 2–4 | 1 | 2–3 | 4–6 |

공통 보조 포즈는 grabStart 2장, release 2장, rest 2–4장, wake 2–3장, stunned 1장이다. 현재 플레이어는 sleep 호흡 루프를 재생하지 않으므로 첫 제작안은 한 장 유지로 한다.

| 행 | 열(0부터)의 제작 예약 | 프로필 키 |
| --- | --- | --- |
| 0 | 0–5 idle(선택 수 4 또는 6) | `idle` |
| 1 | 0–7 오른쪽 보행(선택 수 6 또는 8) | `walkRight` |
| 2 | 비대칭 디자인의 왼쪽 보행 예약. 초안은 1행 반전 | `walkLeft` |
| 3 | 0–2 jump, 3–4 fall, 5–7 land | `jump`, `fall`, `land` |
| 4 | 0–1 grabStart, 2–5 held, 6–7 release | `grabStart`, `drag`, `release` |
| 5 | 0 sleep, 1–4 rest, 5–7 wake | `sleep`, `rest`, `wake` |
| 6 | 0–2 hit, 3 stunned, 4–7 예약 | `hit`, `stunned` |
| 7 | 0–5 look에 담는 종별 특징(선택 수 4 또는 6) | `look` |
| 8 | 추가 포즈 예약. 펭귄 슬라이딩 등은 미연결 | 초안에서 참조하지 않음 |

한 클립은 한 행 안에서만 재생한다. 9행이면 현재 요구를 수용하며 11행(1536×2288)은 승인된 추가 방향·이동 변형이 예약 공간을 넘을 때만 검토한다. 7종 초안 모두 현재 스키마에 들어가므로 이번 설계를 위해 스키마 필드를 추가할 필요는 없다. `loop`는 모든 상태의 재생 모드를 재정의하는 필드가 아니며, 상태 머신 규칙이 우선한다.

초안의 대표 타이밍은 idle 200–250ms/프레임, 보행 75–120ms/프레임, held 150ms/프레임이다. jump 3장은 260ms, land 3장은 130ms, grabStart·release 2장은 120ms, hit·wake 3장은 180ms에 맞춘다. 이 시간은 현재 `ONCE_MS`와 맞춘 제작값이며 프로필에서 이벤트 총 시간을 별도로 바꿀 수 없다. fall은 `loop:false`로 2장 진행 뒤 마지막 그림을 유지한다. sleep은 한 장을 유지한다.

## 제작 순서와 승인 기준

1. **콜덕 먼저**: 단순한 둥근 실루엣으로 접지·뒤뚱 보행·반전·다리 숨긴 수면을 확인하기 쉽다. 기존 고양이·강아지 보행을 복제하지 않고도 공통 상태 계약을 검증할 수 있다.
2. **아기 하프물범 다음**: 정면 얼굴과 배 접지를 함께 검증한다. 발 없는 동물을 기존 anchor로 표시하는 방식, grab·수면 간 신체 크기 유지, 통통한 착지 표현을 확인할 수 있다.
3. 아기 펭귄 → 웰시코기 → 닥스훈트 → 말티즈 → 포메라니안 순서를 제안한다. 뒤뚱 보행 경험을 재사용하고 짧은 다리·긴 몸통·흰 털·큰 꼬리 순으로 실루엣 검수 범위를 넓힌다. 이후 순서는 제작 자료 준비 상황에 따라 조정 가능하다.

첫 동물은 전 시트를 바로 제작하지 않고 **기준 정면/옆모습, 보행 1루프, sleep, held 대표 포즈**를 먼저 승인한다. 다음에 공중·착지·놀람·전환 포즈를 채운다. 제작에 필요한 자료는 오리지널 디자인/허가된 참고, 공개 배포 범위, 털색·무늬·비율 기준, 기준 포즈와 좌우 반전 허용 여부다. 각 동물의 보행 끝→처음, idle→grabStart→held→release, jump→fall→land, rest→sleep→wake를 동일 접지선에서 확인한다.

## 앱 통합 시 메모

- 신규 ID 등록, 선택 메뉴·카테고리·썸네일·패키징은 앱 담당 작업이다. 초안 파일을 자동 등록하거나 기존 9종 카탈로그에 합치지 않는다. 기존 시작 펫 4종·설정 ID 정책은 유지한다.
- `hold / grabbed`라는 제작 용어는 `grabStart`→`held` 상태, 그림은 `grabStart`→`drag`로 연결한다. `hit / startled`는 `hit`, 지속 자세는 `stunned`다. 새 이름 `hold`·`startled`를 이벤트로 보내면 현재 플레이어가 거부한다.
- 특성 연기는 기존 `look`이나 idle·보행에 담는다. `specialTrait`, `slide`, `swim` 클립을 스키마에 쓸 수 있다고 자동으로 상태가 실행되지는 않는다. 펭귄의 보행/슬라이딩 선택, 실제 물범·포메라니안의 추가 바운스는 별도 상태·이동 정책을 앱 담당이 결정할 때 검토한다.
- 긴 닥스훈트와 넓은 꼬리의 포메라니안은 표시·클릭 영역·Draw/발판 접촉을 함께 수동 QA한다. 길쭉한 원화에 맞추려는 이유만으로 이번 단계에서 공통 collider·질량·속도를 바꾸지 않는다.
- `elasticity:0.55`는 기존 프로필의 공통 초기값을 빌린 초안이다. 종별 통통함을 물리 수치로 확정한 값이 아니다. 실제 바운스 사용 여부를 검토한 뒤 앱 담당이 정하며 원화 연기와 중복시키지 않는다.
- 스키마 검증 외에 `row < rows`, 미러 참조와 fallback, 원본 존재·크기·셀의 alpha, 앵커와 프레임별 크기를 확인해야 최종 패키지로 승인할 수 있다. 이번에는 원화가 없어 시각 검증과 Windows 앱 QA를 수행하지 않는다.

## 후순위: 돌고래·범고래

| 항목 | 돌고래 | 범고래 |
| --- | --- | --- |
| 기본 포즈 | 둥근 이마·긴 주둥이를 읽을 수 있는 옆모습 3/4 | 검정/흰색 경계, 등지느러미가 읽히는 옆모습 3/4 |
| walk 대체 | 몸통 굴곡과 꼬리의 상하 움직임으로 유영 | 큰 몸의 느린 굴곡과 꼬리 상하 움직임으로 유영 |
| jump / fall | 몸을 호로 굽혔다 펴는 도약, 하강 시 머리 방향 정리 | 큰 실루엣의 완만한 호, 지느러미가 잘리지 않는 하강 |
| sleep / held / hit | 눈감은 유영 자세 유지 / 지느러미를 모은 놀람 / 짧은 몸 움츠림 | 같은 상태 구조, 흰 무늬 위치와 크기 유지 |
| 좌우 / 시트 후보 | 대칭 무늬면 반전, 9행·192×208 셀 내 충분한 폭 확보 | 좌우 흰 무늬가 다르면 독립 방향, 우선9행·필요시11행 |

현재 `walkRight/Left`에 유영 그림을 넣을 수는 있지만 실제 움직임은 지상 물리를 따른다. 수중 부력·별도 중력·물 표면은 이번 설계에 포함하지 않는다. 긴 몸이 기존 셀에서 너무 작아지면 셀 크기 확장은 로더·렌더·anchor 계약을 함께 검토한 뒤 결정한다.

**물튀김 효과 후보**: 점프 시작 또는 착지 시 한 번만 발생하는 효과로 기록한다. 스프라이트의 본체·anchor와 분리하고, 실제 물 표면이 없는 데스크톱에서 언제 표현할지와 Draw 등 다른 효과와의 관계를 앱 효과 담당이 결정한다. 이번 단계에는 효과 이미지·효과 코드·새 이벤트를 추가하지 않는다.
