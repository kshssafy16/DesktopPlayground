# v1.2 결정과 진행

이 문서는 최신 결정부터 과거 순서로 기록한다. 아래의 450 HP·1.18배 보스, 1.8초 콤보 연계, 이전 툴바/펫 관리 방식은 당시 구현 이력이며 현재 규칙은 이 문서의 상단과 [로드맵](ROADMAP.md)의 `현재 작업 트리 상태`를 따른다.

## 2026-10-15 / v1.2.0 Pre-release 인계

- 앱 작업 `8737c74`를 `feature/v1.2` 원격에 보존했다. 같은 저장소의 별도 worktree `feature/v1.2-animation`은 `5d97c5d`까지 원격 Push된 상태로 확인했다. 병합 시 앱 카탈로그의 콜덕·아기 하프물범만 유지하고, 영업냥 Sleep 0행 0열·하프물범 Idle 7→0→1→2→3→4→5→6열(125ms)을 공통 프로필에 반영했다. 애니메이션 원화, 조립 스크립트, 독립 패키지와 미등록 아기 펭귄은 보존했다.
- 전체 Windows 수동 QA를 마치지 않았으므로 v1.2.0은 Pre-release로 표시한다. 후속 검수: 하프물범 Idle의 잦은 시선 전환, 영업냥 Sleep 실제 표시, 이미지 뷰어·캡처 종료 후 작업 표시줄 Z-order, 장시간 실행 중 종료 여부. 말티즈 재제작과 나머지 신규 펫 등록은 다음 개발 단계다.

## 2026-10-15 / 외부 창 전환 뒤 작업 표시줄과 펫 Z-order 복구

- 원인: `pop-up-menu` topmost를 다시 설정해도 이미 같은 계층인 overlay의 실제 앞뒤 순서는 바뀌지 않는다. 앱 창은 비포커스형이므로 이미지 뷰어·탐색기·캡처 후 외부 창 전환은 기존 `focus/blur` 복구 경로에도 잡히지 않았다.
- Windows의 foreground/taskbar reorder 이벤트를 보조 프로세스에서 구독한다. 전환 후 실제 Win32 순서에서 작업 표시줄이 overlay보다 앞선 경우에만 Electron에 복구 신호를 보내며, `moveTop()`으로 overlay 다음 controls 순서를 포커스 변경 없이 복원한다. 반복적인 bring-to-front 타이머는 없다. Start 메뉴·캡처 UI가 활성화된 동안에는 복구하지 않고 일반 창으로 돌아온 뒤 확인한다. 앱 종료 시 보조 프로세스의 입력 파이프도 닫는다.
- 기존 PC 모드 native shape/클릭 통과, 도구 모드 입력, 전체 화면 좌표, 툴바·Playground 숨김/복원은 유지한다. 보조 프로세스 실행 실패 시 기존 전환 복구만 남고 오류는 lifecycle log에 기록된다. F11 독점 전체 화면, 관리자 권한/보안 데스크톱, 자동 숨김·보조 모니터의 시스템 UI 순서는 Windows 수동 검수 대상으로 남는다.
- 최소 검증: `node tests/window-order.cjs`에서 기존 창 순서·입력 및 외부 foreground 전환 뒤 taskbar 위 복구, 비포커스 확인 통과. 변경 JS 구문 검사와 `git diff --check` 통과. 실제 WebP 뷰어·탐색기·Win+Shift+S 전환은 사용자가 확인한다.

## 2026-10-15 / 마감 전 수면·콤보·보스 연출과 종료 경로 보완

- 실제 Sleep 중인 펫 위에 작은 `z` 두 글자를 시간에 따라 떠오르게 그린다. 별도 파티클/타이머 없이 Canvas에서 계산하며 보조 효과 OFF, 기상·Grab·피격·삭제 시 즉시 숨긴다. Rest와 기존 5~60분 Sleep 지속/기상 규칙은 변경하지 않았다.
- 콤보는 기존 3초 표시·페이드 완료 시 초기화, 최대 999를 유지한다. 마지막 0.6초에 짧게 사라지고, 5/10/25/50 이상 구간은 크기·색을 조금 강조한다. 별도 업적/저장은 없다.
- 보스는 기존 막대 체력바만 유지하면서 첫 0.5초와 처치 후 페이드 중 작고 옅은 원형 반응을 보인다. 체력 20% 이하일 때 막대 색을 바꿔 종료 임박을 알린다. 보조 효과 OFF는 장식만 숨긴다.
- 메인 프로세스의 종료 타이머는 발견하지 못했다. 이전 `before-quit`는 앱 내부에서 요청하지 않은 `app.quit()`도 정리 절차로 넘겼다. 이제 툴바/Tray의 명시적 종료만 정리 후 종료하고, 요청되지 않은 quit은 차단·진단 로그에 남긴다. 시작 실패는 오류를 기록한 뒤 종료하도록 유지한다. 약 3분 후 종료의 실제 원인은 아직 재현·확정되지 않았으므로 Windows 장시간 검수가 필요하다.
- 최소 검증: `node --check renderer.js main.js tests/grab-throw.cjs tests/gun.cjs`를 파일별로 실행, `node tests/gun.cjs`(Gun 24개 및 Grab/Throw 71개), `node tests/smoke.cjs --startup-input-only`, `git diff --check` 통과. 실제 Windows 화면 및 장시간 실행은 수행하지 않았다.

## 2026-10-15 / 보스 종류별 체력·크기와 콤보 페이드 조정

- 보스는 펫 정의 ID별 최대 HP를 사용한다: 슬라임 360, 우사기 390, 얼굴냥 420, 푸들 470, 커비 510, 황색냥 520, 영업냥 550, 실눈냥 560, 커비(잠) 580, 시바 620. 다른 정의는 450 HP를 기본값으로 사용한다. 최대 HP에 따라 체력바 폭도 100~129px로 달라진다. 몸 크기는 기존 1.18배에서 약 1.34~1.44배로 키웠다. 일반 펫의 크기·비살상 규칙과 보스 출현 확률 2.5%는 그대로다. 막대 위 숫자·라벨은 바로 위 최신 결정에 따라 제거했다.
- 콤보 글자는 `COMBO` 18→23px, 숫자 38→49px로 키웠다. 이전 1.8초 연계 제한이 3초 표시/마지막 1초 페이드보다 짧아서, 페이드 중 명중하면 001로 되돌아가던 문제를 수정했다. 이제 새 명중이 페이드 완료 전(<3초)에 들어오면 기존 콤보에 이어지고 표시 시간이 다시 시작된다. 3초가 모두 지나 화면에서 사라질 때 카운터가 초기화된다. 최대 999와 실제 명중에서만 증가하는 규칙은 유지한다.
- 검증: `node tests/gun.cjs`(Gun 23개와 Grab/Throw 71개), 변경 JS 구문 검사 및 `git diff --check` 통과. 실제 Windows에서 확대된 보스·체력바와 콤보 글자의 가독성을 확인해야 한다.

## 2026-10-15 / Bomb 콤보·희귀 보스·수류탄 Draw 충돌

- Bomb도 실제 펫 피해에 성공할 때 공통 콤보를 1회 올린다. Gun·Hammer와 같은 1.8초 연계, 최대 999, 마지막 명중 3초 표시를 유지하며 페이드가 끝나면 카운터를 0으로 초기화한다. 표시 위치는 기존 화면 오른쪽 상단 모서리에서 80px 왼쪽·64px 아래로 옮겼다. 보조 효과 OFF에서는 글자만 숨긴다.
- 사용자가 펫 도구로 소환할 때만 2.5% 확률로 보스 개체가 된다. 시작 펫 3종은 일반 개체로 유지한다. 보스는 기존 펫의 1.18배 크기, 450 HP와 머리 위 체력바를 갖고, 공통 Gun/Hammer/Bomb 피해를 받는다. HP가 0이면 기존 Sleep(없으면 Rest/Idle) 클립으로 1.2초간 페이드아웃한 뒤 해당 인스턴스만 기존 `Pet.remove()` 정리 경로로 삭제한다. 일반 펫은 계속 비살상이다. 원본 이미지와 애니메이션 프로필은 변경하지 않았다. GIF/정적 이미지 패키지에 별도 수면 모션이 없다면 현재 이미지로 페이드하는 한계가 있다.
- 수류탄 이동도 펫과 같은 Draw 선분의 연속 충돌 판정을 사용한다. 직선·자유형·사각형·타원 벽에 반발하므로 닫힌 도형 안에서 폭발할 수 있다. 화면 벽/바닥 반발, 24개 미폭발 상한, 투척 후 약 3초 실제 위치 폭발은 유지한다. Draw 도형은 폭발로 삭제하지 않는다.
- 검증: `node tests/gun.cjs`의 Gun 22개와 상속된 Grab/Throw 71개, `node tests/screen-effects.cjs`, `node tests/smoke.cjs --startup-input-only`, 변경 JS 구문 검사 및 `git diff --check` 통과. 실제 Windows의 보스 표정·HP바 위치, 수류탄의 다양한 손그림 충돌과 콤보 시인성은 수동 확인 대상이다.

## 2026-10-15 / 무기별 화면 파손·콤보·작업 표시줄 검수 보완

- 빈 화면에 닿은 총알은 무기별로 다른 오버레이 균열을 남긴다. AWM은 큰 검은 중심 구멍과 넓은 파손(반경 124px), AK-47은 중간 구멍(71px), UZI는 작은 파손(40px), 더블배럴은 펠릿마다 작은 파손(28px)이다. 펫 명중 시에는 파손 대신 기존 비살상 Hit/데미지 숫자만 유지한다. 망치는 반경 170px(같은 자리 반복 시 최대 200px)의 더 굵은 연결 균열을 사용한다. Bomb은 균열을 만들지 않는다.
- 총·망치로 펫을 실제 명중할 때만 우측 상단 `COMBO 001`부터 증가한다. 마지막 명중 후 1.8초 안에 다시 명중하면 이어지고 최대 999다. 마지막 명중 뒤 3초간 표시하며 마지막 1초에 페이드아웃한다. 보조 효과 OFF는 콤보 글자만 숨기고 판정과 누적은 유지한다.
- 놀이 메뉴에 `균열 지우기`를 추가해 기존 `clear('crack')`만 호출한다. 펫·그림·다른 효과는 보존한다. 누적 균열의 시각 객체 상한은 64개에서 96개로 늘렸고 자동 복구 약 5초와 모드 설정은 유지한다.
- Electron의 `pop-up-menu` 최상위 수준은 Windows 작업 표시줄 위에 놓인다. PC 모드에서는 오버레이의 native shape을 작업 영역과 작업 표시줄에 걸친 펫 주변 구간으로 제한해, 펫이 없는 작업 표시줄 구간의 투명 최상위 창을 제거한다. 펫 영역은 약 150ms 간격으로 위치 변화가 있을 때만 갱신한다. 도구 모드는 전체 화면 입력 영역을 유지한다. 실제 작업 표시줄 밝기와 다중 모니터/DPI 모양은 Windows 사용자가 확인해야 하며, Windows 자체의 활성/비활성 색상 변화까지 통제하지는 않는다.
- 검증: `node tests/gun.cjs`, `node tests/screen-effects.cjs`, `node tests/smoke.cjs --startup-input-only`, `node tests/window-order.cjs` 통과. 변경 JS 구문 및 `git diff --check` 확인. 실제 렌더링의 색·크기, 작업 표시줄 밝기는 자동 검사로 확정하지 않는다.

## 2026-10-15 / Phase 4-B 수동 검수에 따른 단순화와 효과 조정

- `현재 펫 관리`는 인스턴스별 행·번호·종류 선택기·전체 삭제·확인 문구를 제거했다. 실제 펫을 정의 ID별로 묶어 대표 썸네일, 이름, 현재 마릿수와 한 개의 `삭제` 버튼만 3종씩 표시한다. 삭제는 확인 없이 그 종류의 모든 인스턴스를 기존 `Pet.remove()` 경로로 정리하며, 다른 종류와 정의/자산은 유지한다. 페이지 수는 인스턴스가 아닌 종류 수 기준이고 마지막 페이지가 비면 자동 보정한다. Trash 개별 삭제와 Tray의 기존 정리 기능은 별개로 유지한다.

- 커서/툴팁: 기존 Gun·블랙홀 SVG 선형 스타일을 다른 도구에도 적용하고 같은 SVG 파일을 툴바와 CSS 커서가 공유한다. 32×32 커서의 hotspot은 16,16으로 클릭/조준 좌표와 맞춘다. 구조물은 별도 화면 배치 모드가 아니라 ON/OFF 버튼이므로 툴바 아이콘만 적용한다. Gun의 총 PNG·총구/탄도는 변경하지 않았다. 툴팁은 요청된 짧은 문구로 정리했다.
- 표시 전환: 두 번 호출되던 최초 reveal과 show 직후 지연 재배치를 없애고, 가시성이 실제 바뀔 때만 상태 변경 경로에서 창 순서를 보정한다. 툴바 복원 시에만 위치를 확인한다. 화면 크기·DPI·userData 경로·물리·애니메이션은 바꾸지 않았다.
- 최소 검증: `node tests/window-order.cjs` 통과(일반/최대화 창, PC 입력 대상, Hide/Show·트레이, 작업 표시줄 native hit); `node tests/smoke.cjs --startup-input-only` 통과(시작 3종, 도구 CSS hotspot, Gun 메뉴 선택/바깥 클릭 무발사). `node tests/grab-throw.cjs --black-hole-only` 6개 통과로 이전 미커밋 Phase 3-D 보존을 확인했다. 변경 JS 구문, SVG XML 14개, `package.json` 파싱, `git diff --check` 통과. 전체 Electron smoke, 실제 그래픽 캡처, 장시간 테스트는 수행하지 않았다.
- 사용자 수동 확인: 작업 표시줄·Start 메뉴·자동 숨김과 보조 모니터의 예약 영역, Chrome/탐색기/Codex 포커스 왕복, YouTube 재생과 화면 캡처 `Win+Shift+S`, PC 클릭·휠·창 이동, Gun 메뉴 가장자리/커서, 도구 모드 우클릭 복귀, 접기/툴바 숨김/Playground 숨김의 시각적 튐을 확인한다. 작업 표시줄 영역의 펫 픽셀은 정상 조작 우선으로 표시되지 않는다.
