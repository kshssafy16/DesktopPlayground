# 두 Codex 작업 분담 및 모델 추론 사용 지침

## 기본 원칙

- ChatGPT는 제품 의사결정/프롬프트/두 작업 검토.
- **앱 개발 Codex**는 `D:/DesktopPlayground`의 `feature/v1.2`: `main.js`, `renderer.js`, `preload.js`, `controls.*`, `screen-effects.js`, 일반 테스트, 앱 통합과 릴리스.
- **애니메이션 Codex**는 `D:/DesktopPlayground-animation`의 `feature/v1.2-animation`: `animation/`, 로컬 펫 프로필과 독립 미리보기/테스트/문서. 공통 앱 파일을 임의 수정하지 않음.
- 현재 과거 브랜치 `feature/pet-animation`은 통합 이전 코드일 수 있으므로 **최신 main에서 새 브랜치를 생성**. 기존 브랜치는 삭제하지 않는다.
- 두 에이전트는 동일 파일을 동시에 수정하지 않는다. 통합/병합은 앱 담당만 수행하고, 충돌하는 문서 양쪽 내용을 검토하여 보존.
- 앱과 애니메이션 공유 계약은 `pet.json`+프로필+state/events로 하고, 변경 시 명세/테스트와 함께 앱 담당에게 전달.
- 긴 테스트를 자동 반복하지 않는다. 고위험 IPC, 상태 관리, 파일 가져오기 등에만 최소 자동 테스트. 시각/조작감은 사용자가 Windows에서 직접 확인.

## 추론 수준 가이드 (선택 가능한 옵션에 한함)

| 작업 | 추천 reasoning effort | 판단 기준 |
| --- | --- | --- |
| 문서 조사, 경로 정리, 작은 CSS/라벨 | Low | 위치가 명확하고 로직 판단이 적음 |
| 툴바 UI, 메뉴 동선, 프로필 매핑, 일반 기능 | Medium | 속도/정확도 균형 |
| 블랙홀 orbit 경합/창 순서/IPC/로컬 가져오기 보안 | High | 상태 경합, 데이터 무결성, OS 이벤트 위험 |
| 광범위 애니메이션 상태 전환 설계/복잡한 회귀 | High (필요 시) | 여러 모듈 사이 계약 조정 |
| 대규모 리팩터링 또는 반복 실패한 고난도 버그 | XHigh (예외) | medium/high 실패 이유가 구체적일 때만 |

모델 이름 및 추론 수준 지원 여부는 사용 가능한 Codex 설정에 따라 달라진다. 추론을 올리는 것보다 **작업 범위를 작게 쪼개는 것**이 먼저다.

## 사용량 절감 규칙

1. 매 요청에 `먼저 변경 파일과 결정사항 검토; 이미 구현된 부분 재작성 금지` 명시.
2. Phase 하나씩, 한번에 2~5개 정도의 실제 파일만 수정. 필요한 경우 예외 기록.
3. 전체 저장소 광역 검색·대량 이미지 캡처·테스트 무한 반복 금지.
4. 처음에는 변경 JS `node --check` + 핵심 단위 테스트 1개 + `git diff --check`로 최소 확인.
5. 중단 시 현재 Git diff 및 남은 작업을 짧게 기록하고, 사용량 회복 후 이어서 실행. reset/restore/force 금지.
6. 큰 스프라이트 신규 생성은 Codex가 아니라 별도 이미지 제작으로 처리하고, Codex는 메타데이터/연결 담당.
7. 프롬프트는 `목표 / 허용 파일 / 보존 / 완료 조건 / 금지` 형식으로 간단하게.
8. 단순 작업은 빠른 모델 또는 낮은 노력, 설계/경합만 높은 노력. 외부 AI 추론 서버는 현재 Electron 앱에 도입할 필요 없음.

## 추후 런타임 AI를 넣는 경우

현재는 상태 머신과 프로필, 물리, 이벤트 중심 설계가 적합하며 **실행 중 AI 추론은 필요하지 않다**. 향후 NPC 대화가 필요하면 기본 오프라인 대사/규칙부터 고려하고, 온디바이스 LLM 또는 외부 API는 개인정보·성능·비용·사용자 동의를 따로 검토한 뒤 opt-in으로 제안한다.
