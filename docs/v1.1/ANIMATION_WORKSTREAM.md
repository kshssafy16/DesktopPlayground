# DesktopPlayground v1.1: Animation Workstream

상태: 계획 및 작업 역할 정의. 이 문서는 코드 구현 완료를 의미하지 않는다.
기준 프로젝트: `D:\DesktopPlayground`, 기준 개발 브랜치 `feature/v1.1`.

## 1. 목표

여러 펫에 공통으로 적용할 애니메이션 재생 규칙과 펫별 프로필을 분리한다. 캐릭터별 원본 spritesheet의 프레임 구성과 모습은 다르며, 모든 행이 동일한 행동을 뜻한다고 가정하지 않는다. 기존 Grab/Throw/자율 점프/외부 충격 구분, 클릭 통과, UI, 구조물, 펫 무제한 생성 정책을 유지한다.

## 2. 작업 소유권과 충돌 방지

- **앱 개발 채팅**: `D:\DesktopPlayground`의 `feature/v1.1`. 물리 및 구조물, 도구, UI, 트레이, 전체 회귀와 최종 통합 담당.
- **애니메이션 채팅**: 권장 작업 디렉터리 `D:\DesktopPlayground-animation`의 `feature/pet-animation`. 우선 `docs/v1.1/animation/`, 펫 애니메이션 프로필, 독립 미리보기와 관련 테스트만 수정.
- 두 작업은 **같은 `renderer.js`, `main.js`, `controls.js`를 동시에 수정하지 않는다**. 새 애니메이션 채팅은 최초 단계에서 해당 파일 읽기만 한다.
- 애니메이션 모듈 연결이 필요해지면 원래 앱 작업을 잠시 멈추고 **한 명의 통합 담당**이 현재 HEAD에 반영한다. 통합 전에는 커밋/브랜치 상태와 변경 목록을 반드시 확인한다.
- 원본 `assets/pets/**/pet.json`, `spritesheet.webp`, 내부 ID와 사용자 데이터 경로는 함부로 이름을 바꾸지 않는다. 새 이름은 표시 이름으로 처리한다. 직접 자산 수정이 필요한 경우 원본을 보존하고 diff/근거를 남긴다.
- 실사용 시각품질에 대한 마지막 판단은 `npm start`에서 사용자가 한다. 프레임/회귀 테스트 통과만으로 시각적 자연스러움을 확정하지 않는다.

## 4. 공통 상태 및 애니메이션 재생 규칙

### 필수 이동/동작 상태 후보

- `idle`, `look`, `roam/walkLeft/walkRight`, `rest`, `sleep`, `wake`.
- `jumpPrepare` (선택), `jumpRise`, `jumpApex`, `fall`, `land`.
- `grabStart`, `held`, `release`(천천히 놓기), `thrown`, `bounce`, `hit`, `stunned`(선택).
- `climbUp`, `climbDown`, `blackHoleOrbit`, `consumed/remove`.

물리/게임플레이 상태와 시각 애니메이션 상태는 분리한다. 모든 펫에 모든 상태별 고유 이미지가 있을 필요는 없다. 프로필에서 fallback을 정의한다. 실제 기본 동작과 모션을 임의로 바꾸지 않는다.

### 클립 재생

- `loop`: idle, walk 등. 클립에 지정된 유효 프레임 0부터 마지막 유효 프레임까지 재생한 후 반복하며, 빈 프레임은 순서에서 제외한다.
- `once`: grabStart, land, hit, wake 등. 반복하지 않고 마지막 프레임 유지 또는 후속 상태로 전환한다.
- `hold`: held, sleep 등에서 적절한 자세 유지 또는 느린 루프.
- 클립별 `{row, frames 또는 frameIndices, fps, loopMode, fallback, flipX, transform/anchor}` 등의 데이터를 지원한다. 좌우 반전 가능 여부는 시트별로 결정한다.
- 상태 전환 시 프레임을 적절히 시작/유지하되, 매 tick마다 0으로 리셋하거나 중간 프레임을 건너뛰지 않는다. 우발적인 flicker, 미세한 1프레임 자세 점프를 피한다.
- 자율 행동 전환보다 Grab, Throw, 외부 충격, Black Hole, 등반이 우선한다. 착지 뒤 잔류 충격/바운스 없이 자율 상태로 돌아간다.
- 프레임 진행은 경과 시간 기반. 30/60/144Hz 환경에서 동일 시간 동안 비슷한 애니메이션 시간을 유지한다.

### 시각적 크기와 물리

- **캐릭터의 기준 신체 크기**는 상태 전환 시 유지한다. 점프/낙하 그림이 원본 셀 안에서 작게 생성돼 있으면 이미지 bounding box, 기준 신체 중심과 바닥 anchor를 이용해 *필요한 프레임에서만* 보정한다.
- 펫별 신체 크기는 서로 다를 수 있다. 소품/책상/복장 포함 프레임은 프레임 전체 경계가 아니라 **펫 몸통을 기준으로 비교**한다. 의도된 웅크림, 늘어짐, 착지 squash는 허용한다.
- 발이 평평한 지면에서 떠 보이거나 박히지 않도록 클립별 anchor를 설정한다. 시각적 transform 때문에 물리 collider가 달라지지 않게 한다.
- 사용자 Grab/Throw의 바운스는 유지하고, 펫 자율 점프는 착지 시 추가 바운스가 없어야 한다.
- 새로운 이모지, Zzz, 임의 소품, 안경, 말풍선 등을 만들어 덧붙이지 않는다. 기존 시트의 원치 않는 장식은 클립에서 제외한다.

## 5. 단계별 구현/검수

1. **분석 전용**: 실제 시트, `pet.json`, 최신 코드, 이전 QA 프리뷰를 대조해 9종의 사용 가능한 클립과 빈 셀, 원본 결함/코드 결함을 분류. 영업냥의 이전 좌우 표현에 대한 근거를 기록.
2. **독립 애니메이션 규격**: 공통 상태표/재생 방식 및 펫별 프로필을 독립 파일로 정의. 최초에는 `renderer.js`를 수정하지 않는다.
3. **QA 미리보기/테스트**: 9종 각각에 대해 `idle → walkRight → walkLeft → jump → apex/fall → land → rest/sleep`, `grabStart → held → release`, `grabStart → thrown → bounce → land`, `hit → recover` 전환을 프리뷰. 실제 클립이 없으면 fallback 표시를 명시한다.
4. **통합**: 앱 개발 채팅과 변경 충돌을 확인한 뒤 단일 담당자가 런타임 연결. 물리/클릭 통과/구조물/효과 회귀, 실제 Windows 수동 확인을 수행한다.
5. **확장**: 말티즈, 포메라니안, 웰시코기, 오리, 하프물범 및 개인 로컬 추가 펫은 같은 프로필 규격을 재사용한다. 원본 패키지가 기준 규격과 다르면 검증된 변환/어댑터를 사용한다.

## 6. 완료 조건

- 서로 다른 애니메이션 상태에서 펫 신체의 크기와 발 기준점이 의도치 않게 요동치지 않는다.
- 원래 있던 좌우 보행 프레임을 근거 없이 대기 fallback으로 대체하지 않는다.
- 첫 프레임부터 마지막 유효 프레임까지의 루프와 one-shot 이후 복귀가 끊기지 않는다.
- Grab 전/중/후, Throw/착지, 자율 점프/착지, 충격 후 회복 등의 전환이 예측 가능하다.
- 9종 테스트 미리보기와 변경 전후 비교가 프로젝트의 QA 자료로 남는다. 테스트에서 정상이어도 실제 사용자가 본 시각적 문제를 우선 해결한다.
- 문서 및 QA 업데이트. 통합 전에는 portable build, push를 하지 않는다.

## 7. 차기 버전 아이디어 기록 (구현 보류)

- 파닥몬, 테리어몬, 치이카와, 쿠리만쥬, 펭구 등 캐릭터를 개인용 로컬 펫 패키지로 추가. 새로운 에셋 제작 및 저작권/재배포 정책 검토는 나중에 별도 결정.
- **고정형 펫/NPC 모드**: 사용자가 위치를 고정하면 배회는 멈추고 그 자리에서 idle/look/rest/반응 애니메이션만 수행. 말 걸기/짧은 대사는 추후 검토. PC 입력 통과를 방해하지 않아야 한다.
- **펫별 특수 스킬**: 예를 들어 커비 전방 부채꼴 흡입. 스킬은 기존 물리 상태와 자율 상태를 안전하게 중단/복구하는 확장점으로만 설계하고 지금 구현하지 않는다.
- **게이미피케이션/다마고치**: 한 펫 선택·성장, 사용 시간 기반 경험치, 공부/코딩 시간, 밥 주기 등. 사용자가 수용하기 전까진 **기록만** 하며 구현과 데이터 수집은 하지 않는다. 학습 시간 측정이나 앱 추적은 개인정보/UX 설계가 필요하다.
