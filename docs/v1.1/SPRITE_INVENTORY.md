# DesktopPlayground v1.1 — 전체 9종 Sprite Inventory

최신 Grab 회귀 보완은 [animation/GRAB_REGRESSION.md](animation/GRAB_REGRESSION.md)를 따른다. 9종 row5 Held 반복·얼굴냥 울음·시바 눈물과 영업냥 row1/2의 **전체 셀** 보행을 복원했다. 아래6절의 영업냥 단일 기립 walk/금지행 기록은 이전 단계이며 jump/fall fallback에만 남는다. 원본 WebP/metadata는 동일하다.

> 기준: 사용자가 제공한 `pets.zip` (2026-10-13). 패키지 9개, 각각 `pet.json` + `spritesheet.webp`. 실제 로컬 `feature/v1.1`의 최신 renderer는 여기에 포함되지 않았으므로, 구현 결정은 해당 브랜치 코드를 확인하여 확정한다.

**문서 우선순위:** 기존 `SPRITESHEET_AUDIT.md`(일부 5종만 분석)의 내용을 이 문서가 대체한다. 특히 얼굴냥의 안경은 **9행 3~4열(1-based)**로 확인됐다. 기존 문서의 8행 기록은 잘못된 것이므로 중복된 지침을 업데이트하거나 `superseded`로 표시한다.

## 1. 파일 구조와 호환성

- 모든 시트는 **1536px 너비, 8열, 셀 크기 192×208px**이다. 9행은 1536×1872, 11행은 1536×2288.
- 일부 셀은 비어 있고 **1행은 9행 시트에서 6프레임, 11행 시트에서 7프레임**이다. 행 번호는 이 문서에서 **1-based**, 코드의 `row`는 0-based로 명시해 혼동하지 말 것.
- 대부분의 9행 시트에는 프레임 수 `6,8,8,4,5,8,6,6,6`, 11행 시트에는 `7,8,8,4,5,8,6,6,6,8,8`이 존재한다. 이는 픽셀 존재 검사이고 안전한 애니메이션의 보장은 아니다.
- 이전에 별도로 표시된 브라우저 첨부 이미지 일부는 1374×2048처럼 축소됐지만 **이 ZIP의 9개 WebP는 모두 원본 공통 셀 크기**이다. 브라우저 표시 이미지로 원본을 덮어쓰지 말 것.

## 2. 캐릭터별 실제 이미지 관찰

**아래는 시트 내용으로 추정한 후보 동작이다.** 정확한 clip 매핑은 실행 프리뷰와 의미 검수 후 확정한다.

### 황색냥 (`cat_brown`)

1행 정면 대기, 2행 오른쪽 이동, 3행 왼쪽 이동. 3행 일부 얼굴/팔다리 연결이 어색해 보일 수 있으므로 오른쪽 이동 반전을 우선 비교. 6행에는 웅크림/잠이 보여 rest 후보. 10~11행 시선 전환 후보.

### 얼굴냥 (`cat_face`)

몸이 없는 얼굴형. 2~3행은 입 열린 얼굴이 대부분이라 실제 보행 표현과 다름. 9행 3~4열(1-based)에 원본 안경과 손가락이 확인됨: 기본 애니메이션 후보에서 제외. 8행의 치아 노출 표정도 의도치 않은 반복 재생 금지. 10~11행은 좌우 보기 후보.

### 실눈냥 (`cat_sleepy`)

1, 4, 6~9행에 웅크린/졸린 자세가 있음. 2~3행은 달리는 모습이어서 활발한 상태에만 사용. 휴식 중 비자연스러운 걷기 전환 방지.

### 영업냥 (`salary-cat`)

1행은 뒤집힌 책상/컴퓨터 소품 자세, 2~3행은 등/측면 계열, 4행은 다른 캐릭터 등장, 7~9행은 컴퓨터 활동 등 소품 포함. 표준 idle/walk/fall에 기계적으로 대입하지 말고 실제 연출/발 위치를 확인. 의도치 않은 다른 캐릭터가 갑자기 나오지 않게.

### 시바 (`doge`)

1행 대기, 2~3행 좌우 이동, 5행 점프/달리기 후보. 6행은 슬픈/눈물 표정이 있어 잡기 또는 피격 표현 후보. 8~9행은 보행/시선 표현 후보.

### 푸들 (`puddle`)

1행 대기, 2~3행 이동 시 푸른 소품을 문 모습. 사용자가 일반 걷기에서 소품을 원치 않으면 기본 walk로 자동 배정하지 않기. 4~5행 손 올림/뛰기, 6행 졸림, 10~11행 시선 전환 후보.

### 커비 (`kirby`)

1행 대기, 2~3행 걷기, 4행 손 흔듦, 5행 점프/눌림, 6행 슬픔/주저앉음, 9행 화난 표정 후보. 감정 상태와 물리 상태를 구분.

### 커비(잠) (`kirby_sleepy`)

1행 대기/졸림, 2~3행 보행, 5행 이동/점프 후보, 6행 눈 감음/앉기, 8행 큰 하품 또는 흡입 자세. 8행을 걷기나 기본 idle에 섞지 않음. 향후 개인 스킬 후보로만 기록.

### 우사기 (`usagi`)

1행 대기, 2~3행 보행, 4행 손 흔듦, 5행 점프 후보. 6행 울먹임/누움, 7~9행 표정 변화가 강해 상황에 맞게 선택. 기본 이동에서 표정 행을 무작위로 섞지 않기.

## 3. 자동 검사가 실제로 확인한 것

- 9개 WebP 모두 RGBA 디코딩이 가능하고, 모든 셀이 192×208로 분할된다.
- 각 행의 사용 셀은 시작 열에서 연속이다. 나머지 빈 셀까지 반복 재생하지 않는다.
- alpha > 20 기준, 원본 셀의 가시 픽셀은 셀 바깥으로 넘지 않으며 경계 픽셀을 접촉하지 않았다. 하지만 **잘림, 품질 불량, 불연속 동작이 없다는 뜻은 아니다.**
- 프레임의 시각적 몸 크기와 발/중심 위치는 캐릭터와 동작별로 큰 차이가 있다. alpha bbox만 같게 만드는 자동 확대/축소는 금지한다.

## 4. 수정 원칙과 확인 대상

1. 기본 이름, 폴더, `pet.json.id`는 서로 다른 개념이다. **표시명은 변경해도 내부 ID와 원본 ID는 기본적으로 보존**한다. 폴더명 변경 시 `local-pets.js`, package allowlist, 기존 사용자 설정과 테스트를 함께 마이그레이션해야 하므로 명확한 이득이 없으면 변경 금지.
2. 코드와 별개인 에셋 원본은 수정 전 SHA-256으로 비교하고 별도 백업한다. 변경 시 어떤 셀을 왜 바꿨는지 기록한다.
3. 얼굴냥의 원본 안경/손가락은 9행 3~4열에 있다. **프레임 제외**가 우선이며, 원본을 손상시키는 삭제나 이미지 전체 재생성은 하지 않는다.
4. 펫별 `clip -> frames, anchor, mirror/fallback` 매핑은 `PET_ANIMATION_PLATFORM.md` 기준으로 관리한다.
5. 각 펫에서 대기↔걷기, 좌↔우, 휴식↔수면, 잡기→던지기→착지를 실제 1x/2x 렌더 프리뷰로 검수한다.

## 5. 출처·권리

ZIP의 이미지들은 앱에 이미 복사되어 있던 로컬 펫 패키지이며, `pet.json`만으로는 공개 재배포 허가가 확인되지 않는다. 개인 추가 패키지와 공개 배포 자산은 분리하고, 기존 `ASSET_SOURCES.md`를 기준으로 관리한다.

### 최종 선택 이유와 남은 한계

- 푸들: 최신 요청에 따라 **원본1/2행8장 보행을 복원**했다. 실제 보행감이 우선이며 기존 시트에 그려진 푸른 소품은 함께 표시한다. 새 소품을 추가한 것이 아니다. gait/head 크기를 위해 고정scale1.1만 적용하고 crop이나 원본 교체는 하지 않는다. 낮은 측면 몸통/소품은 원본 포즈 특성으로 남는다.
- 얼굴냥: 몸·다리가 없는 얼굴형이므로9행 시선 전환10장과 좌측반전으로 방향을 표현한다. scale1.035, tilt .035rad, 최대약1px의상향bob를 elapsed-time으로 적용한다. 중심origin을 유지하며 안경/손가락/치아금지행은 그대로 제외한다.
- 영업냥: idle/Look의8행노트북,Rest의6행키보드와 **이동/공중의4행2열 단일 기립 포즈**를 분리한다. 좌측은기립포즈반전. 이는 실제보행이아닌명시적fallback이며 발걸음자산부족은남는다. 업무소품이있는상태와없는기립상태의형태차이는의도된구분이다.
- 우사기: 중간공중3장의원본높이는146/147/148px로idle196px보다작았다. scale1.25로약183/184/185px가되게하고, sourcecolumns1/2/3의foot을185/208,153/208,194/208로명시하여셀안에구워진점프높이가물리점프에중복가산되지않게했다. 귀/몸의의도된포즈차이는유지한다.
- 황색냥/실눈냥/시바/커비/커비(잠)는원본과기존프리뷰를재검토하고기존정상프로필을그대로보존했다.5종프로필JSON이수정전후동일함을확인했다.새장식이나수면텍스트는없다.
- 로컬Sprite는walk진입|vx|>.5,유지>.15의표시전용hysteresis로정지경계의idle/업무클립깜빡임을줄인다. 안정된휴식/Grab/Throw/orbit/등반우선순위와물리속도에는영향이없다.
