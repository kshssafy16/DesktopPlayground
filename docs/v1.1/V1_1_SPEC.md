# DesktopPlayground v1.1 제품 명세

최신 시각 회귀 보완: GrabStart 후 Held에서 원본 표정을 반복하고 영업냥 초기 좌우 이동을 복원한다. [개별 매핑/제한](animation/GRAB_REGRESSION.md)이 이전 단일 기립 walk·Held 고정 기록을 대체한다. 새 물리/도구/이미지는 추가하지 않는다.

상태: 개발 중. Phase 2-B까지 구현, 실제 Windows 수동 QA 별도. 2026-10-13 최신 사용자 요구 반영.
진행 갱신: Phase 3-A 화면 효과 관리와 독립 애니메이션 플랫폼의 Electron 연결까지 완료. 신규 도구/블랙홀 확장은 미구현이며 실제 Windows 동적 시각 품질은 수동 QA로 남는다. [통합 계약](animation/RUNTIME_INTEGRATION.md) 참고.
기준 소스: `kshssafy16/DesktopPlayground`의 v1.0.0. 이 문서는 과거 Phase 문서를 삭제하거나 교체하지 않는다.

## 1. 제품 목표

DesktopPlayground는 Windows 화면 위에 펫을 가볍게 방치하면서, 잡기와 던지기, 화면 타격 효과로 스트레스를 완화하는 소형 데스크톱 앱이다.

우선순위:
1. 일을 하면서 펫이 자연스럽게 움직이거나 쉬는 모습이 귀여울 것
2. 잡거나 던지고 맞힐 때 반응이 즉각적이고 재미있을 것
3. PC의 클릭을 방해하지 않고 화면을 즉시 정리할 수 있을 것
4. 장시간 실행 및 여러 펫과 효과의 동시 사용에서 상태가 꼬이지 않을 것
5. 원하는 개인용 캐릭터를 소스 수정 없이 추가할 수 있을 것

실제 Windows 화면, 파일, 프로세스를 부수는 앱이 아니다. 충격, 균열, 파편, 탄흔은 투명 오버레이에만 그린다. 런타임 외부 HTTP(S) 요청은 사용하지 않는다.

## 2. 기존 기능과의 호환

유지:
- 시작 펫 정확히 4종: Slime `blob`, 황색냥 `cat_brown`, 시바 `doge`, 커비 `kirby` 각 1개
- Sprite 기반 펫은 기존 목록을 보존. 기본 Canvas 펫 선택 목록에는 슬라임만 노출
- 펫 추가는 기존처럼 계속 가능. **하드 cap 20 금지**, 임의 자동 삭제 금지. 10~20마리는 대표 테스트 규모일 뿐이다
- PC click-through, 클릭 도구에서 우클릭하면 PC 복귀, 접기 시 PC 복귀
- Pet Touch와 Trash의 개별 인스턴스 삭제
- 기존 Draw 종류, 색상, 굵기, 그리기 충돌체, 지우개, 전체 지우기
- Platform/Ladder의 공유 구조, 기본 시작 OFF, 설정과 기존 로컬 데이터
- Playground 표시/숨김과 Tray, offline portable 실행

변경:
- 펫의 자율 걷기 비율을 전반적으로 낮추고, 캐릭터별 활동성과 휴식 패턴을 분리
- 잡기와 던지기 속도 추정 개선, 속도 덮어쓰기 방지, 착지와 타격 반응 강화
- 블랙홀 최대 2개에서 최대 10개로 확장. **기존 흡수 완료 후 삭제 유지**
- 망치, 총 추가. 폭탄에 화면 균열 효과 추가, 공통 균열 모드 제공
- 툴바 재배치, 현재 펫 관리, 로컬 펫 패키지 가져오기 지원
- 펫별 생성 구조물의 색상/장식 차별화
- 신규 오리지널 캐릭터 5종은 자산이 준비된 후 단계적으로 적용

## 3. 캐릭터 행동과 활동성

기본 행동은 `roam`, `idle`, `look`, `rest`, `sleep`, `jump`를 작은 상태 머신으로 구현한다. `grabbed`, `thrown`, `hit`, `knockout`은 자율 행동보다 우선하는 외부 상태다. 등반과 구조물 이동은 멈춤 상태와 충돌하지 않도록 우선순위를 명시한다.

캐릭터별 프로필은 데이터로 설정한다. 예: `activity`, `restBias`, `jumpBias`, `idleDurationRange`, `lookChance`, `sleepChance`. 아래 값은 **초기 밸런스 방향**이며 확정된 물리 숫자가 아니다.

| 그룹 또는 펫 | 활동성 | 행동 특징 |
| --- | --- | --- |
| Slime | 보통 | 말랑하게 움직이며 탄성, 표정 변화 |
| 황색냥 등 일반 고양이 | 낮음 | 걷는 시간보다 쉬는 시간이 길고 가끔 주변 관찰 |
| 얼굴냥 | 보통 | 표정 중심, 이동 거리 짧게 |
| 실눈냥 | 매우 낮음 | 휴식, 잠듦 비중 높음 |
| 영업냥 | 낮음 | 짧게 움직이고 소품과 쉬는 자세 강조 |
| 시바 | 높음 | 활발한 이동과 점프, 단 휴식 구간도 있음 |
| 푸들 | 보통 | Phase 2-A 최신 요청: 보통 활동성, 배회와 휴식 병행 |
| 우사기 | 매우 높음 | 짧고 재빠른 이동, 깡충 뛰기 |
| 커비 | 보통 이상 | 가볍게 이동, 탄성 및 표정 강조 |
| 커비(잠) | 매우 낮음 | Phase 2-A 최신 요청: 매우 차분함. 2-B에서 기존 눈 감은 프레임으로 수면 표현 |
| 말티즈 | 보통 이상 | 작은 걸음, 호기심 |
| 포메라니안 | 높음 | 통통 뛰기, 복슬한 몸 표현 |
| 웰시코기 | 보통 이상 | 짧은 다리 이동, 발랄한 점프 |
| 오리 | 보통 | 뒤뚱거리기, 놀랐을 때 날갯짓 |
| 하프물범 | 낮음 | 엎드려 쉬기, 배로 미끄러짐 |

전반적인 기본 roam 비중은 v1.0.0보다 낮아야 한다. 모든 펫이 동시에 계속 걷는 현상을 피하고, 같은 종이라도 상태 타이밍에 작은 변화를 둔다. 프로필 범위와 전환 주기는 수동 관찰로 조정한다. 이름만 `Sleepy`이고 계속 뛰는 상황이 없어야 한다.

스프라이트가 없는 행동은 무리하게 가상의 행을 선택하지 않고 idle/walk/fall 클립 및 가벼운 scale/tilt로 표현한다. 공통 클립 인덱스를 패키지별 실물과 대조한다.

## 4. Grab, Throw, Collision, Knockout

- 드래그 시작 시 포인터와 펫 중심의 offset을 유지한다. 잡을 때 펫이 순간이동하지 않도록 한다.
- 마지막 두 이벤트 차이가 아닌 최근 80~120ms 포인터 시각/좌표로 throw 속도를 계산한다. 최근 움직임이 없으면 거의 정지 상태로 놓인다.
- 던진 뒤 외부 충격이 유효한 동안 자율 이동이 vx/vy를 덮어쓰지 않도록 한다. 자연 감쇠 후 roam/rest로 복귀한다.
- 화면 가장자리, 바닥, Draw 벽 및 발판에서 충돌 후 반발을 주되 짧은 떨림이나 무한 반동은 방지한다.
- Sprite에도 landing squash/rebound 적용. 엉뚱한 행을 선택하거나 발이 떠 보이지 않도록 render anchor와 collider를 확인한다.
- 폭탄/망치 피격은 당황, 눌림, 밀려남의 단기 반응이다. 펫을 즉시 삭제하지 않는다.
- 총 피격은 `hit -> knockout -> remove instance` 단계를 거친다. 여러 번 맞아도 삭제 큐를 중복 실행하지 않는다. 같은 정의의 다른 펫은 남는다.
- 타격, 쓰러짐은 **비유혈 카툰 연출**. HP나 육성 시스템은 새로 만들지 않는다.

## 5. 장난감과 이펙트

### Bomb
- 클릭 즉시 폭발, 충격파와 파편, 가벼운 화면 흔들림, 국소 균열이 생긴다.
- 펫은 거리 기반으로 밀려나며 실제 삭제되지 않는다.
- 기존 효과 cap과 정리 규칙을 살리고 연속 클릭의 짧은 cooldown을 검토한다. 효과 때문에 프레임이 급락하지 않아야 한다.

### Hammer
- 클릭 지점에 망치 타격 연출. 화면 균열/파편이 생기고 펫에 직접 맞으면 충격 상태와 반발이 발생한다.
- Bomb은 넓은 폭발, Hammer는 좁고 선명한 타격으로 시각적으로 구분한다.
- 펫을 직접 맞혀도 삭제하지 않는다.

### Gun
- 포인터로 목표를 조준하고 클릭해 발사하는 장난감. 초기 구현은 **즉시 명중 판정 + 짧은 탄환 궤적**을 우선한다. 궤적 시작점 등 정확한 디자인은 코드와 UX 검증 후 결정 가능하다.
- 명중: 피격 스파크 -> 독자적인 게임풍 데미지 숫자 팝업 -> 쓰러짐 애니메이션 -> 페이드/작은 파티클과 함께 해당 인스턴스 제거.
- 숫자 연출: 밝은 노랑/주황 계열, 진한 외곽선, 약한 흔들림과 위로 튀며 사라짐. 메이플스토리의 타격감을 참고하되 글꼴, 그래픽, 사운드 자산을 복제하지 않는다.
- 실제 HP 없음. 숫자는 시각적 데미지 표현이며 게임 밸런스 수치가 아니다.
- 빗나감: 짧은 화면 탄흔만 생성. 다른 Windows 창에는 영향을 주지 않는다.
- 동시에 보이는 탄환/궤적 효과와 damage popup에는 cap, 수명, 화면 밖 즉시 정리 정책을 둔다. 초기 목표는 탄환 시각 효과 최대 24개, 수명 2초 이내.
- 자동 연사 또는 복잡한 탄도 계산은 첫 구현 범위에서 제외할 수 있다. UI/도구 사용감이 확인된 뒤 확장한다.

### Black Hole
- 동시에 최대 10개 생성 가능.
- **흡입 -> 3.5회가량 회전 -> 중심에서 해당 펫 인스턴스 삭제**라는 기존 핵심 동작을 보존한다. 기존의 `방출` 선택 UI는 도입하지 않는다.
- 11번째 생성 시 가장 오래된 블랙홀을 안전하게 정리하고 새것으로 교체하는 방식 제안. 삭제되거나 Touch로 분리된 펫의 궤도 상태가 남지 않아야 한다.
- 서로 다른 블랙홀의 영향이 겹칠 때 한 펫이 두 궤도에 동시에 속하지 않도록 한다.
- 효과 수명과 회전 시간은 경과 시간 기준. 10개 동시 사용 시 FPS와 펫 상태를 확인한다.

### 화면 균열 공통 설정
- `자동 복구`: 균열이 몇 초 후 자연스럽게 사라짐 (초기 실험 약 5초)
- `누적 유지`: 지우기 전까지 균열을 보존하되 렌더와 메모리 부담을 막는 안전 제한 필요
- `균열 초기화`: Draw 지우기와 독립적인 동작. 그림 충돌체나 펫을 삭제하면 안 됨
- 화면 타격 효과는 오버레이 렌더링이며 실제 화면 캡처/변조를 하지 않는다.

## 6. 구조물

- 구조물은 `world.structures`의 공유 지형으로 유지한다. 생성한 펫이 사라져도 기존 lifecycle로 관리한다.
- 구조물에 `styleKey` 또는 creator의 종/캐릭터를 기록해 펫별 색상, 발판 가장자리, 사다리 장식을 다르게 한다.
- 고양이는 캣타워/발바닥, 강아지는 나무/뼈, 커비는 별, 오리는 연노랑, 하프물범은 연하늘색 얼음 등을 기획 기준으로 한다.
- 기존 7 Platform, 5 Ladder, cooldown, 충돌, 가림 및 정리 규칙을 먼저 유지. 밀도 증가는 수동 검증 이후에만 결정한다.
- 캐릭터를 구분할 수 없거나 자료가 없으면 안전한 기본 스타일을 사용한다.

## 7. 조작창과 관리

펼친 툴바 목표: `PC | 펫 | 만지기 | 놀이 | 그리기 | 더보기 | 접기`.

- `놀이`: Bomb, Hammer, Gun, Black Hole의 선택 UI. 최근 선택한 도구를 기억해 빠르게 재선택할 수 있으면 좋다.
- `펫`: 이미지 썸네일, 카테고리, 현재 떠 있는 인스턴스 목록과 개별/전체 삭제, 로컬 펫 가져오기.
- `더보기`: 구조물 ON/OFF, 균열 자동/누적 설정 및 초기화, Playground 표시/숨김, 툴바만 숨김, 앱 종료.
- `접힌 툴바`: Playground 표시/숨김, 펼치기, 더보기. 단 사용감 확인 후 세부 조정 가능.
- `툴바만 숨김`: 펫은 계속 보임. Tray 메뉴로 복구 가능해야 한다. 현행 `Ctrl+Alt+Shift+P`는 **PC 모드 복귀** 단축키이므로 툴바 복구가 되지 않는다. v1.1에서는 새 복구 단축키를 따로 제공하거나, 기존 동작을 해치지 않는 안전한 확장안을 검토한다.
- `Playground 숨김`: 펫/그림/효과와 오버레이를 감추고 입력을 반환. 다시 표시하면 안전하게 PC 모드로 복귀.
- `펫 인스턴스 삭제`: 선택한 1개만 지움. `가져온 패키지 제거`: 사용자 라이브러리의 자산 삭제로 구분, 별도 확인.
- 우클릭 PC 복귀, 정상 클릭 통과 및 기존 controls 위치 저장을 지킨다.

## 8. 커스텀 펫과 공개/개인 자산

- 내장 펫은 현재처럼 app `assets/pets`에서 관리한다.
- 사용자 가져오기는 `pet.json` + `spritesheet.webp`를 우선 지원. 임의 JavaScript/실행 파일 금지.
- 원본 Codex Pet 형식의 8x9 또는 8x11 스프라이트 규격을 읽되 앱 전용 metadata, clips, anchor, 성격을 확장 가능하게 한다.
- userData 아래 별도 라이브러리에 안전하게 저장. 파일명, 경로, 파일 크기, 디코딩 크기, ID 충돌, 잘못된 JSON과 행/열을 검사하고 오류를 UI에 알린다.
- 공개 배포본에 포함하지 않는 유명 캐릭터는 사용자 로컬 패키지로만 추가한다. 이미 공개된 v1.0.0의 자산 권리 문제는 별도의 배포 검토 대상으로 남긴다.
- PNG/GIF 1장 간편 import는 우선순위가 낮으며 고품질 애니메이션 패키지에 집중한다.

## 9. 제외 및 변경 제어

v1.1에서 기본적으로 제외: 온라인 펫 마켓, 계정/클라우드, 소리, AI 대화 기능, 펫 성장 시스템, 실제 화면 파손, 멀티모니터 전면 재설계.

새로운 아이디어가 나와도 바로 코드에 추가하지 않는다. 구현 중 기획 변경이 더 낫다고 판단하면 `DECISIONS_AND_PROGRESS.md`에 변경 전/후, 이유, 영향, 테스트, 사용자 승인 여부를 기록하고 진행한다.

## Phase 2-B 확정 동작 (2026-10-13)

- 펫 간 물리 충돌/밀어내기를 제거한다. 같은 위치에 겹칠 수 있으며 다른 펫과의 거리로 위치·속도를 강제 보정하지 않는다. 지형/Draw/Platform one-way/사다리와 기존 탐색은 유지한다.
- 표시 이름은 황색냥(`cat_brown`), 얼굴냥(`cat_face`), 실눈냥(`cat_sleepy`), 영업냥(`salary-cat`). 기존 ID/경로/pet.json/저장된 선택과의 호환성을 보존한다. 카테고리는 기본/고양이/강아지/캐릭터만, 기본에는 슬라임만 표시한다.
- 2-A의 Roam/Idle/Rest/Look 시간·확률·활동성은 유지한다. 수면은 실눈냥·커비(잠)의 안정된 Rest 표현이며 별도 영구 상태/새 AI를 추가하지 않는다. Grab/Throw/orbit/강한 착지/공중/등반이 우선한다.
- 기존 시트에 검증된 휴식·표정 자세만 사용한다. 없는 클립은 느린 idle/미세한 호흡/시선 fallback. 황색냥 왼쪽 걷기 원본의 분절 오류는 정상 오른쪽 행 반전으로 우회하며 원본 이미지는 보존한다.
- Tray의 **보조 효과 표시** 체크로 공통 `auxiliaryEffectsEnabled`를 전환한다. 기존 schemaVersion 1 설정 파일의 선택 필드로 저장하고 없는 값은 ON이다. Canvas 땀방울/폭탄 보조 링·파티클·섬광·화면 흔들림을 숨긴다. 기본 자세·호흡·착지 squash, Draw, 폭탄 자국과 블랙홀 본체, 물리/흡입/삭제는 유지한다. 확정 클립에 의도적으로 선택한 원본 표정/소품은 기본 이미지이므로 숨기지 않는다. 생성 Zzz/이모지/말풍선/장식은 추가하지 않는다.
- 향후 말풍선·피격 이펙트·데미지 숫자도 같은 설정을 따른다. 이번 단계에서 망치/총/신규 캐릭터/스킬/툴바 개편은 구현하지 않는다.
- 향후 개인용 패키지 후보: 파닥몬, 테리어몬, 치이카와, 쿠리만쥬, 우소우소. 캐릭터별 특수 스킬(예: 커비의 전방 부채꼴 범위 다른 펫 흡입)은 별도 기획·승인 단계로 남긴다. 펫 간 기본 충돌 제거와 명시적으로 발동하는 향후 스킬의 상호작용은 구분한다.

### Phase 2-B 품질 보완 확정 (2026-10-13)

9종은 definition.animation을 참조하는 개별 프로필로 idle/walk/jump/fall/drag/rest/sleep/look의 실제 프레임 목록·경과시간·fallback·고정anchor를 사용한다. 공통 행 의미를 가정하지 않는다. 얼굴냥의 안경·손가락(row8, col2/3:0-based), 영업냥의 분절/다른 캐릭터/전복책상은 기본 재생에서 제외한다. 최신 사용자 피드백에 따라 푸들은 원본 소품 포함 좌우 보행을 복원한다. 황색냥 좌측은 정상 우측 반전을 유지하고 생성 Zzz를 제거한다. 얼굴냥은 실제 시선 전환과 좌측반전·미세 기울임으로 이동 방향을 표현하고, 영업냥은 업무 자세와 단일 기립 이동/공중 fallback을 분리한다. 우사기의 공중 표시 배율·프레임 발 기준점을 보정한다. 원본 자산/내부ID는 보존한다.

자율 점프는 움직임 원인을 표시하고 일반 낙하와 함께 바닥/Platform/Draw 착지 시 vy=0으로 정리한다. 짧은 squash와 착지 보호 후 기존 자율 행동으로 돌아간다. Throw와 Bomb은 외부 충격 소유권으로 구분하여 강한 반발을 유지하고 안정화/기한 종료 후 소유권을 정리한다. Throw 입력·물리 상수와 거리/높이는 보존하며 전역 restitution을 낮추지 않는다. 상세 프로필과 원인별 물리는 SPRITE_INVENTORY/PET_ANIMATION_PLATFORM의 최신 확정절을 따른다.
