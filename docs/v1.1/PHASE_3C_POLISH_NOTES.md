# DesktopPlayground v1.1: Phase 3-C 사용감 보완

작성 목적: Phase 3-C 구현 완료 후 사용자 실사용 피드백을 반영한다. 기존 작업 트리 보존. 대규모 리팩터링과 신규 기능 확장 금지.

## 1. 4종 Gun 표시 방향

- 기존 `awm.png`, `ak47.png`, `uzi.png`, `double_barrel.png`를 그대로 사용한다.
- 총 몸체가 거꾸로 보이거나 총구가 커서 반대편을 가리키지 않게 방향을 검수한다.
- 최신 사용자 지시: 총은 기본적으로 커서 오른쪽 아래(4시 방향)에 있고 총구가 왼쪽 위(10시 방향)의 레드도트를 향해야 한다. 화면 가장자리에서는 다른 방향으로 옮겨 잘림을 피한다.
- PNG 원본을 다시 제작하지 않고 총기별 기준 방향, muzzle anchor, Canvas 회전/반전 및 render scale로 해결한다.
- 총구 섬광과 투사체 출발점도 실제 총구와 일치시킨다. 커서 좌표와 피격 판정의 일치는 유지한다.
- 화면 가장자리에서는 잘림 방지를 우선하고, 필요한 경우 방향/오프셋을 전환해도 총구는 레드도트를 향하게 한다.

## 2. 9종 Sleep 표정 수정

- 실제 수면 프레임은 편안한 표정, 눈 감기, 몸 웅크리기, 안정적인 자세를 우선한다.
- 울음, 눈물, 불쌍함, 맞음, 놀람, 당황, 통증 표정은 수면 클립에서 제외한다.
- 얼굴냥 등 실제 수면 프레임이 부족한 펫은 차분한 대기/휴식 표현을 대체로 사용한다.
- 수면 진입, 수면 유지, 기상은 각각 적합한 클립 또는 fallback을 사용하고, 기존 5~60분 수면 지속 정책을 보존한다.
- 원본 spritesheet 변경, 프레임을 잘라내는 임의 crop 및 이모지/Zzz 추가 금지.

## 3. 수류탄 투척 방향

- 기본 클릭 투척은 왼쪽 / 오른쪽 / 정면(화면 내 거의 수직 방향의 중앙 포물선)의 세 경향 중 하나를 랜덤하게 선택한다.
- 정면은 실제 3D 이동이 아니라 2D 투사에서 수평 성분이 적은 투척으로 표현한다.
- 세 방향 모두 좌우로 흔들리는 편향이 없도록 한다. 투척 속도와 포물선은 기존 물리 범위 내에서 조절한다.
- 드래그 투척은 사용자가 정한 방향을 우선한다. 기본 클릭일 때만 랜덤 선택한다.
- 약 3초 타이머, 벽/바닥 충돌, 폭발 위치, 비살상 Hit 및 상향 충격을 유지한다.

## 4. 도구별 커서

- PC 모드: OS 기본 커서, 마우스 클릭/휠 통과 유지.
- 펫 생성: 선택 상태가 이해되는 작은 커서/미리보기.
- 잡기: open hand, 실제 잡은 동안 closed/grabbing hand.
- 그리기: 펜촉, 지우개 모드: 지우개 기준점(hotspot)과 실제 드로잉 좌표 일치.
- 수류탄: 기존 수류탄 PNG 또는 간소화된 아이콘으로 커서 표시.
- 망치: 기존 해머 PNG 기반 클릭 전 위치 표시, 실제 충격 위치와 머리 접촉점 정합.
- 총: 선택 무기 PNG와 레드도트. 총구가 커서를 향해야 한다.
- 블랙홀: 작은 소용돌이/원형 타겟. 주변 OS 조작 방해 금지.
- 모든 커서는 고DPI 스케일을 고려하고 컨트롤 툴바 위에서는 일반 포인터를 사용한다.
- CSS cursor로 가능한 경우 우선 사용한다. Canvas 그리기 커서를 사용한다면 브라우저 기본 커서와 이중 표시되지 않게 하고 실제 입력 좌표와 일치시킨다.

## 5. 화면 전체 및 작업 표시줄

- 월드와 오버레이 창의 화면 경계를 `display.workArea`(작업 표시줄 제외)가 아니라 `display.bounds`(물리 디스플레이 전체) 기준으로 검토한다.
- 작업 표시줄 위에도 펫/도구/효과를 표시할 수 있도록 하되 OS 작업 표시줄 버튼과 마우스 휠/클릭 사용을 가로막으면 안 된다.
- PC 모드 click-through와 기존 최상위 표시 기능 유지.
- 하단 경계는 전체 화면 최하단으로, 상단 개방 규칙은 그대로 유지.
- 단일/다중 모니터의 좌표 변환, 음수 모니터 좌표, DPI 배율을 확인한다. Windows 작업 표시줄 최상위 계층의 제약은 무리해서 우회하지 않고 기록한다.

## 6. Hammer 타격 및 균열

- 망치가 한 프레임 깜빡였다 사라지는 현상을 수정한다.
- 기존 hammer.png를 이용해 짧은 예비 동작 -> 타격 -> 반동 또는 복귀 애니메이션으로 연결한다. 권장 가시 시간 약 300~550ms.
- 망치 머리 접점에서 충격 이펙트 발생. 짧은 충격 스파크와 유리 파편이 바깥으로 이동해야 한다.
- 균열은 순간 생성 완료되는 대신 약 150~350ms 동안 중심에서 외측으로 뻗고 분기한다.
- 여러 번 같은 곳을 때리면 더 큰 손상으로 확장된다. 현재 자동 복구(약 5초)/누적 모드 유지.
- 멀리까지 직선만 뻗는 거미줄 같은 균열이나 화면 전체 덮는 효과는 피하고, 유리 파손처럼 짧고 굵기 다른 불규칙 선으로 표현한다.
- Hammer, Bomb, Gun의 데미지 및 비살상 Hit 경로 변경은 최소화한다.

## 7. 구현/검증 범위 제한

- 이미 잘 작동하는 총기별 발사 간격, 산탄, 비살상 데미지, 수류탄 3초 타이머, 상단 개방, 던지기, 착지, 활동성, PC/Tray는 유지한다.
- 다른 worktree를 수정하지 않는다. 메인 브랜치 병합, 빌드, commit, push 금지.
- 불필요한 대량 테스트/캡처/프리뷰 제작 금지. 변경 JS 구문 검사 및 꼭 필요한 최소 점검만 한다. 실사용 손맛과 시각적 검수는 사용자가 직접 한다.
- 문서에는 변경된 규칙과 수동 확인 사항만 간결하게 반영한다.
