# Phase 2-B 최종 Sprite 시각 QA

`index.html`을 브라우저에서 열면 수정 전후를 캐릭터별로 비교할 수 있다. 서버나 제품 빌드 없이 상대 경로의 캡처 파일을 읽는다.

- `before.webp` / `after.webp`: 실제 Electron `Pet.draw` 캡처, 무손실 32프레임·100ms 간격·3.2초 반복.
- `before.png` / `after.png`: 같은 캡처의 첫 프레임.
- `before-profiles.json` / `after-profiles.json`: 캡처에 사용한 프로필과 renderer SHA-256.
- 마지막 열: 대기→우측 이동→좌측 이동→점프→낙하→착지 squash→휴식→잡힘. 궤적은 표시 비교용 합성이며 실제 물리 영상이 아니다.

원본 9종 시트는 변경하지 않았다. 이 폴더는 기존 자산을 포함하는 개발 QA 자료이며 현재 제품 package allowlist에는 포함되지 않는다.

## 재현

저장된 before는 이번 변경 직전의 기준 자료다. 현재 코드의 after를 다시 캡처하려면:

```sh
node tests/smoke.cjs --sprite-preview --qa-after
python tests/encode-sprite-preview.py after
```

인코더는 Pillow가 있는 개발용 Python이 필요하다. 제품 실행에는 Python이 필요하지 않다. 캡처 테스트는 격리 userData를 사용하며 원래 설정을 변경하지 않는다. before를 의도적으로 다시 설정할 때만 `--qa-before`와 인코더의 `before` 인자를 사용한다.

## 확인 결과와 한계

9종 원본 및 기존 프리뷰를 비교했다. 브라우저 반복 재생의 여러 시점에서 푸들 보행, 얼굴냥 방향감, 영업냥 기립/업무 자세, 우사기 공중 크기와 전체 전환을 확인했다. 자동 검사는 각 선택 프레임의 범위·alpha·기준점·1x/2x·변형을 확인한다. 이 결과만으로 실제 앱의 시각적 만족도를 합격 처리하지 않는다.

- 푸들은 원본 좌우 보행과 함께 원래 그려진 푸른 소품이 보인다. 소품 없는 보행을 원하면 별도 자산 작업이 필요하다.
- 얼굴냥은 실제 시선 전환과 좌측 반전·미세한 기울임/상향 움직임을 사용한다. 얼굴형 캐릭터에 다리를 만들지 않았다.
- 영업냥의 이동/공중은 단일 기립 대체 자세다. 업무 자세로 미끄러지지는 않지만 실제 발걸음 애니메이션이 없고, 정지 시 책상 소품이 다시 나타나는 원본 자세 차이는 남는다.
- 우사기는 공중 scale 1.25와 source-column 발 보정으로 작아짐/이중 상승을 줄였다. 귀와 몸의 원래 포즈 변화는 유지한다.

## 사용자가 실제 `npm start`에서 확인할 항목

1. 9종을 생성해 3분 이상 대기·좌우 이동·자율 점프·착지·휴식을 관찰한다. 푸들의 8프레임 보행과 원본 소품이 원하는 표현인지 확인한다.
2. 얼굴냥의 좌우 시선·기울임이 자연스럽고 안경/손가락/Zzz가 없는지 확인한다.
3. 영업냥의 업무↔기립 이동 전환과 실제 보행 부재를 받아들일 수 있는지 확인한다.
4. 우사기의 실제 점프·최고점·하강·착지에서 갑자기 작아지거나 발이 튀지 않는지 확인한다.
5. 모든 펫의 Grab→느린/빠른 Throw→착지·휴식, 방향 전환, 화면/Draw/발판 위 접촉을 확인한다. 자율 점프 추가 바운스 없음과 Throw/Bomb 반발은 기존대로여야 한다.
6. 60/144Hz, 100/125/150% DPI와 투명 화면에서 크기·깜빡임·선택 위치를 확인한다. 캡처의 1x/2x 확대는 실제 DPI/주사율 테스트가 아니다.
