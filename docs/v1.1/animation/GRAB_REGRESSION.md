# Grab/Held 및 영업냥 이동 회귀 수정 (2026-10-14 최종 보완)

시작 작업 트리에는 직전 플랫폼 통합의 미커밋 변경이 있었다. 이를 유지한 채 player의 잡힘 재생, 관련 프로필·테스트·QA만 보완했다. 최초 보완의 영업냥 내부 crop은 2026-10-14 사용자 요구에 따라 제거했다. 별도 애니메이션 worktree, 원본 metadata/WebP, 물리/활동성/효과/UI/설정 경로는 변경하지 않았다.

## 원인과 재생 규칙

통합 player의 `held: ['drag','hold']`와 index 0 고정이 9종의 기존 표정 변화를 멈췄다. 이를 **GrabStart 120ms once → Held loop**로 고쳤다. 모든 종의 GrabStart는 검증된 2장/각60ms이며 조기 Release/Throw는 기존처럼 즉시 중단한다. Held는 유효한 원본 drag 프레임 목록을 순서대로 반복한다. 한 장뿐이면 hold로 처리한다. Sleep/KO 등의 hold나 Throw/착지 물리는 바꾸지 않았다.

아래 row/column은 **0-based**이다. 9종 모두 실제 원본 row5를 직접 비교했다. 다른 행의 의미가 같다고 가정해 새 상태에 일괄 배정하지 않았다.

| 펫 | Held row5 columns | 복원한 표현 |
| --- | --- | --- |
| 황색냥 | 0,1,2,6,7 | 처진 눈·고개 숙임·회복 반복. 몸 전체가 눕는3~5는 제외 유지 |
| 얼굴냥 | 0,1,2,3,4,5,6,7 | 눈물 고임→울음→회복. 기존에 빠진2~5 복원. **금지 안경/손가락은 row8 col2/3**이며 계속 제외 |

| 영업냥 | 0,1,4,5 | 기존 당황/울먹이는 자세 반복. 원본 프레임만 사용 |

GrabStart는 각 표의 첫2장이고 얼굴냥만0,2(평상→눈물 고임)를 사용한다. 기존 Held geometry를 유지하되 얼굴냥의 새 울음 프레임을 포함한 고정 union 기준점과 GrabStart의 선택2장 union만 다시 계산했다. alpha bbox를 프레임마다 자동 정규화하거나 확대하지 않는다. 의도된 눈/입·웅크림 변화는 남는다.

원본 전체 행도 다시 스캔했다. 다음 숫자는 **row 0부터 순서대로** alpha>16 유효 프레임 수이며, 각 행의 유효 열은 0부터 해당 수−1까지다. 선택 클립의 상세 열·반복 시간은 [실제 프로필](../../../animation/profiles.v1.json)에 있다. Sleep/Look 전용 클립이 없는 경우 표의 대체 행을 쓴다. Release/Landing은 idle, Throw는 fall을 사용한다.

실제 셀에 픽셀이 있어도 표정/소품/분절 때문에 채택하지 않은 열이 있다. 행별 유효 수를 그대로 클립 길이로 쓰지 않았으며 모두 프로필의 선택 목록과 원본 픽셀을 대조했다. 9종 공통으로 GrabStart row5 두 장 once, Held row5 선택 프레임 loop다.

## 영업냥의 초기 이동 복원

`git show v1.0.0:renderer.js`는 우측row1·좌측row2, 각col0~7·5 reference frames(83.33ms), 표시size×2.5·중심offsetY10이었다. 해당 **원래 drawImage 식**을 실제 Electron Canvas에서 재생한 `legacy-salary.png`를 비교했다. 과거 태그 전체 앱을 실행하거나 바꾼 것은 아니다.

원본에는 몸 위로 분리된 둥근 덩어리/연결선과 마지막col7의 불완전한 몸이 있다. 원본 파일을 고치지 않고 초기 좌우 행과 순서를 복원하되 다음 표시 보정만 적용했다.

- 우측row1/좌측row2의 **0~6**, 각83.33ms 반복. 원본 좌우 행이므로 추가 flip 없음. col7 제외.
- **192×208 원본 셀 전체**를 drawImage로 그린다. 내부 이미지 crop은 제거했다. 0~6열의 alpha>16 bbox는 좌우행 모두 x50~142, y9~199로 거의 일정해, 공통 `center=.5`, `foot=199/208`을 적용한다. Pet.size/collider와 기존 size×2.5 표시 배율은 유지한다.
- 중단된 중간안의 crop 적용 화면과 프로필은 `qa/grab-regression/interim-cropped-*`로만 보존한다. 제품과 최신 프리뷰에는 적용하지 않는다. 마지막7열은 원본 몸이 불완전하게 보여 보행 목록에서 제외한다.
- 업무 idle(row8), 키보드 rest(row6), jump/fall의 기존 기립 fallback(row4 col2), drag scale.9는 유지한다.

원본 일부 프레임의 분리된 머리/몸·연결선/회전 자세와 책상↔이동의 외형 차이는 남는다. 원본 전체를 보이면서 이 조각을 보이지 않게 하는 설정은 없다. 이 한계를 숨기기 위해 정지 업무 자세로 이동하거나 새 이미지를 만들지 않았다.

## 실제 실행과 자동 검증

`node tests/grab-visual.cjs before`, `after`는 **현재 프로젝트에서 npm start**를 띄워 실제 RAF와 네이티브 Pet.draw를 사용한다. DOM 포인터 이벤트를 CDP로 자동 전달하며 물리 마우스 장치는 별도 확인이다. 기존 앱이 인스턴스 lock을 보유하면 테스트가 연결 실패하고 그 앱을 종료하지 않는다. 일반 앱 실행과 동일한 사용자 설정을 읽으며 설정 초기화/삭제/선택 변경 API는 호출하지 않는다.

9종 각각 실제 `npm start`에서 **3.2초 Held** 관찰: 이전 캡처는 전부1개 소스 프레임, 최신 캡처는400ms 간격2.4초 이미지와3.2초 추가 sample에서2~6개가 확인됐다. 30/60/144Hz 자동 검사에서는 Held를3.2초 유지해 **전체 유효 프레임이 순서대로 반복**됨을 검사했다. Release/빠른 Throw/실제 바닥 Landing·정상 복귀도 실제 RAF에서 검사했다. Landing 검사는 낮은 높이/속도로 초기조건을 맞춘 후 실제 물리를 진행하며 이벤트를 직접 위조하지 않는다.

기존 회귀+통합14개 = 중복 제외119개 PASS, 별도 animation-platform/local-pets/Electron smoke PASS. native81상태/401선택프레임·1x/2x·기준점·반전,17상태×9종×3시점459렌더 PASS. 기존418개와의 수 차이는 drag QA가 새2장 GrabStart를 선택하기 때문이며 Held 전체 루프는 별도 검증한다. 원본9시트의 모든9/11행·8열 alpha>16 존재를 스캔하고 모든 프로필 참조가 실제 비어 있지 않은 셀임을 확인했다. 초기속도/0.5초거리/최고높이는 작업 시작 renderer snapshot과30/60/144Hz 전부 동일했다.

[전후 QA](../qa/grab-regression/index.html)와 sample JSON/프로필/소스SHA를 보존했다. Native 캡처에서 얼굴냥 울음,9종 고개/표정 순환과 영업냥 좌우 이동·발 기준선을 직접 비교했다. 실제 사람의 마우스 사용감, DPI/주사율·장시간 방치의 최종 만족도는 사용자 확인으로 남긴다. build/commit/push, 새 도구/캐릭터/툴바는 진행하지 않았다.
